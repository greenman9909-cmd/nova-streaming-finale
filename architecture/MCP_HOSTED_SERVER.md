# Nova Stream - Hosted MCP Server (Implementation Plan)

## 📌 Goal
Create a publicly accessible **MCP Server** (Model Context Protocol) that allows external agents (like the Jotform AI Agent) to securely query the Nova Stream database and real-time sports data.

## 🏗️ Technical Architecture
-   **Runtime**: Node.js / Bun.
-   **Transport**: **SSE (Server-Sent Events)** - Required by Jotform.
-   **Authentication**: **OAuth2** (Bearer Tokens generated by a local auth route).
-   **Deployment**: Vercel or Netlify (Public HTTPS).

---

## 🛠️ Proposed Tools (Capabilities)
The MCP server will expose the following tools to the Jotform Agent:

### 1. `get_live_sports`
-   **Input**: `sport` (optional filter).
-   **Logic**: Proxies the existing `nova-backend/api/sports/matches/live`.
-   **Output**: JSON list of live matches, scores, and stream status.

### 2. `search_content`
-   **Input**: `query` (string), `type` (movie/series/anime).
-   **Logic**: Proxies the TMDB search via the backend.
-   **Output**: Best matches with descriptions and release dates.

### 3. `check_watchlist`
-   **Input**: `email` (user identification).
-   **Logic**: Queries the Supabase `watchlist` table (read-only).
-   **Output**: Items currently in the user's list.

---

## ⚡ Step-by-Step Execution
### Phase 1: SSE Infrastructure
1.  Initialize a new Hono/Express project for the MCP server.
2.  Install `@modelcontextprotocol/sdk`.
3.  Implement the SSE transport handler (Standard MCP spec).

### Phase 2: OAuth Handshake
1.  Create a simple OAuth2 flow (`/authorize`, `/token`) that Jotform can use to authenticate the connection.
2.  Store a persistent `CLIENT_ID` and `CLIENT_SECRET` in the `.env` for the handshake.

### Phase 3: Tool Integration
1.  Connect the MCP tools to the **Nova Backend API**.
2.  Implement type-safe tool definitions using JSON Schema.

### Phase 4: Production Deployment
1.  Deploy to a public URL (e.g., `https://nova-mcp.vercel.app`).
2.  Provide the **SSE URL** to the user for the Jotform configuration.
